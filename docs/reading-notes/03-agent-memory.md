# 第三篇：用户记忆 —— 让 Agent 记住你

> 原文：[走进 AI Agent 第三篇（掘金）](https://juejin.cn/post/7682394398210932763)，作者「老王以为」，2026-09。
>
> 主题：会话结束即失效的是上下文管理；本篇解决跨会话持久化——如何让 Agent 在下一次对话中仍然记得用户。

## 记忆的本质

记忆不是把聊天记录原样存下来，而是**主动构建用户的预测模型**：通过专门的 LLM 调用做选择性、抽象化、结构化的提取。

与上下文的区别：生命周期（单次 vs 跨会话）、存储介质（窗口 vs 数据库）、可审查性（可查可改）。

## 记忆的层次结构

```text
轨迹（trace）：单次会话、append-only 流水账
用户长期记忆：跨会话、可改写的档案
业务状态：任务阶段的抽象（如"退货流程第 2 步"）
```

三套正交分类不要混淆：层次（轨迹/长期/业务状态）、格式（Notes/JSON Cards）、认知类型（情景/语义/程序记忆）。

## 四种存储格式与选型

| 格式 | 特点 | 适用 |
|---|---|---|
| Simple Notes | 极简，O(1) 读写 | 快速起步 |
| Enhanced Notes | 叙事完整 | 需要上下文连贯 |
| JSON Cards | 结构化分类 | 需要字段级更新 |
| Advanced JSON Cards | 含 backstory/person/relationship | 复杂用户建模 |

选型是"简单性与表达力之间的权衡"——从最简单的格式开始，出现真实痛点再升级。

## 进阶表示

- **User as Code**：用可执行 Python 保存记忆，擅长聚合统计、冲突发现、约束执行。
- **User as Engram**：写入模型参数的哈希记忆表 + 共享推理 LoRA。
- **多模态参数化记忆**：保存人脸、嗓音等无法文字化的感知。

三者构成"由外及内"的表示介质连续谱：外部存储 → 参数化 → 模型内部。

## 框架案例

| 框架 | 核心思路 |
|---|---|
| Mem0 | 提取—对比—决策流水线（ADD/UPDATE/DELETE/NOOP） |
| Memobase | 画像 + 事件记忆，缓冲批处理 |
| MemGPT/Letta | 模型自管理分层存储 |
| Zep/Graphiti | 时序知识图谱 |

## 评估：三层次框架

- 学术基准 LoCoMo：人类约 88%，早期 RAG 方案约 41%。
- 递进三层：基础回忆 → 多会话检索 → 主动服务。
- 记忆压缩三策略：重要性评分、聚类压缩、抽象泛化；用版本化做冲突检测。

## 隐私保护

- PII 风险与脱敏两难；本地小模型（Ollama + Qwen3）脱敏召回率可达 95%+。
- 设计原则：最小化收集、分层脱敏、可审计、可删除、防泄漏、防记忆注入。

记忆注入是新的攻击面：恶意内容一旦进入长期记忆，会在后续所有会话持续影响模型。
