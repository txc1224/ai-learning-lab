# 第四篇：知识获取管道 —— RAG 基础

> 原文：[走进 AI Agent 第四篇（掘金）](https://juejin.cn/post/7687422041256689691)，作者「老王以为」，2026-09。
>
> 主题：让 Agent 掌握训练数据之外的领域知识——知识怎么进来、怎么被检索。本篇是 RAG 上篇；下篇讲知识组织与深度检索（RAPTOR、GraphRAG），最终与用户记忆汇合成"双层记忆架构"。

## RAG 概述

```text
RAG = 检索器（找相关片段） + 生成器（LLM 基于片段作答）
```

核心价值：无需重新训练即可利用新知识，可溯源、易更新；相比微调成本低、周期短。

## 文档分块（Chunking）

- 为什么要分块：嵌入模型长度限制 + 检索需要精准注入相关内容。
- 三种策略：
  1. 固定大小切分（带重叠）——最简单。
  2. 递归/结构感知切分——生产默认。
  3. 语义切分——按主题边界。
- 常见起点：每块 256-1024 token，重叠 10%-20%。
- 固有缺陷：分块天然切断上下文（下篇的主题）。

## 稠密嵌入（语义理解）

- 嵌入 = 文本 → 向量；语义相近则向量相近，用余弦相似度衡量。
- 演进：Word2Vec（静态向量，无法处理一词多义）→ BERT → BGE-M3 等上下文感知模型。
- ANN 索引：
  - HNSW（基于图，支持增量插入）。
  - ANNOY（基于树，构建快但不支持增量更新）。

## 稀疏嵌入（关键词匹配）

- 词袋模型：TF-IDF → BM25。
- BM25 两个参数：k1 控制词频饱和，b 做长度归一化。
- 倒排索引 = `Map<关键词, 文档ID[]>`；BM25 透明可复算，适合审计。
- 学习型稀疏检索（SPLADE、BGE-M3 稀疏分支）兼具语义泛化能力。

## 混合检索

- 互补性：稠密懂语义但可能漏关键词；稀疏精确但不懂同义词。
- 三阶段流水线：

```text
并行检索（稠密 + 稀疏）
→ RRF 融合（只看排名不看得分）
→ 跨编码器重排序精排
```

- 度量指标：recall@k、MRR、nDCG。
- 核心结论：**没有哪种单一检索策略在所有场景下都可靠**。

## 多模态信息提取

| 路线 | 保真 | 成本 |
|---|---|---|
| 原生多模态处理 | 最高 | 最高 |
| 提取为文本 | 丢失版式信息 | 便宜 |
| 工具化分析（轻量摘要+按需深入） | 中 | 中 |
