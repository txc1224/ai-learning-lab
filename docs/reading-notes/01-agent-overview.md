# 第一篇：走进 AI Agent —— 总览

> 原文：[走进 AI Agent（掘金）](https://juejin.cn/post/7670003108343513122)，作者「老王以为」，2026-08。
>
> 本笔记是蒸馏版，只保留核心概念与结论。

## 核心公式

```text
Agent = 决策引擎（LLM） + 信息视野（上下文） + 执行通道（工具）
```

三者缺一不可：模型决定"多聪明"，上下文决定"知道什么"，工具决定"能做什么"。

## 关键概念

### ReAct 循环

Agent 以"思考（Thought）→ 行动（Action）→ 观察（Observation）"循环运行。执行轨迹（trajectory）是调试和优化的关键资产——出问题时先看轨迹，而不是先换模型。

### 工具的四种形态

1. 预定义工具（最常用，对应第 7 课 ToolRegistry）。
2. 按需技能（渐进加载，对应第二篇 Skills）。
3. 动态代码（受控生成并执行）。
4. 子 Agent（隔离执行、回传结论）。

工具设计三原则：单一职责、描述清晰、失败可恢复。

### 上下文是信息架构

不是"把所有东西塞进 prompt"，而是设计哪些信息、以什么结构、在什么时机进入模型视野。

### 接口视角

观察空间和动作空间决定 Agent 能力边界。与其等待更强的模型，不如设计更好的接口——这句话是整个系列的立意。

### Harness 工程

围绕模型构建的工程层（上下文管理、工具调度、约束验证、可观测性）决定 Agent 的下限。模型决定上限，Harness 决定下限。

### 范式演进五阶段

```text
提示工程 → 上下文工程 → Harness 工程 → 循环工程 → Graph 工程
```

逐层叠加，不是互相替代。

### 安全护栏三层

```text
输入侧（注入检测、来源标记）
→ 执行侧（权限、沙盒、白名单工具）
→ 输出侧（内容审查、引用校验）
```

人工干预是最后一道防线。安全是架构问题，不是事后补丁。
