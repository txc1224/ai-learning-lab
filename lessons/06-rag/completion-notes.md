# 第 6 课完成笔记：RAG

## 1. RAG 解决什么问题？

模型参数不是你的私有文档。RAG 先检索外部资料，再把相关片段放进上下文，降低凭空回答的概率。

## 2. 为什么要切分文档？

整篇文档太大且噪声多；分片让检索更精确，也能控制上下文长度。每个 chunk 保留来源和序号，便于引用。

## 3. 关键词检索和向量检索的区别？

本课关键词检索匹配字面词，透明、便宜、易调试；向量检索通过 Embedding 匹配语义，通常更适合自然语言，但依赖模型和向量存储。

## 4. 召回和生成为什么要分开评估？

检索没找到正确片段时，模型再强也可能答错；检索正确但模型没有正确引用，也属于生成问题。需要分别观察 hits 和最终答案。

## 5. 引用有什么作用？

引用告诉用户答案依据了哪个来源和分片，也帮助开发者定位错误召回。引用不是证明模型一定正确，但能提高可追溯性。

## 6. 本课如何连接聊天？

```text
用户问题 → retrieve → buildContext → system/user context → Provider
```

下一步可以把 `buildContext` 接入 `ChatService` 的 `ChatMessage[]`。

## 已验证与边界

本地文档清洗、切分、关键词召回和上下文拼接可无外部服务运行。真实 Embedding、向量相似度质量、pgvector 和大规模检索尚未验证。

## 记忆卡片

```text
Chunk：可检索的文档片段
Embedding：文本向量表示
Retriever：找相关知识
Context：交给模型的检索结果
Citation：回答来源
Recall：找没找到
Generation：模型怎么答
```
