# 第 4 课完成笔记：LLM API 与 Provider

## 1. 为什么需要 Provider 抽象？

模型厂商的请求字段、错误格式和流式协议可能不同。`ChatProvider` 把业务需要的能力固定下来，具体供应商藏在适配器内部。

## 2. Mock Provider 有什么价值？

它让我们在没有 API Key、没有网络和不想产生费用时，验证上下文组装、错误处理、UI 和数据库链路。它不代表真实模型质量。

## 3. Prompt 和上下文有什么区别？

Prompt 是指令内容；上下文是整个请求可见的信息集合。历史消息、检索片段和工具结果都属于上下文。

## 4. Token 估算为什么不能当账单？

不同模型的 tokenizer 不同，字符长度只是近似值。生产账单应优先使用供应商返回的 usage，并记录模型版本。

## 5. 为什么模型输出仍要校验？

模型输出即使被要求 JSON，也可能缺字段、类型错误或包含额外文本。解析和业务校验必须在程序中完成。

## 6. 哪些错误可以重试？

临时网络错误、429 和部分 5xx 通常可以有条件重试；配置错误、权限错误和参数错误不应重试。写入数据库前还要考虑幂等。

## 7. 本课如何连接对话工作台？

当前流程从 mock 文本升级为：加载历史 → 组装消息 → Provider 生成 → 保存 assistant。下一课会把完整生成换成增量事件。

## 已验证与边界

已完成 Provider、Mock、OpenAI 兼容接口、ChatService 的类型检查；默认路径不需要真实 API。真实供应商鉴权、usage 准确性和生成质量需要单独 smoke test。
