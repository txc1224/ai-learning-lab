# 第 3 课练习

## 练习 1：启动数据库

执行 Docker Compose 命令，并确认 postgres 容器为 healthy。

## 练习 2：阅读 schema

解释：

- 为什么 `conversations.id` 是主键？
- 为什么 `messages.conversation_id` 是外键？
- 为什么消息查询需要索引？
- `ON DELETE CASCADE` 有什么影响？

## 练习 3：完成对话闭环

依次执行：

1. 创建会话。
2. 查询会话列表。
3. 追加一轮消息。
4. 查询会话详情。
5. 重启 API。
6. 再次查询会话详情。

## 练习 4：观察错误边界

测试：

- 不存在的会话 ID。
- 缺少 `title`。
- 空白 `title`。
- 空白 `content`。
- 非法 JSON。

记录每个输入的状态码和响应体。

## 练习 5：理解事务

暂时让 assistant 插入语句失败，观察用户消息是否也被回滚。完成后恢复代码。

## 练习 6：思考幂等

如果客户端因为网络超时重复发送同一条消息，现在会发生什么？

写下一个后续改进方案，例如：

```text
请求携带 idempotencyKey
→ 数据库建立唯一约束
→ 重复请求返回第一次结果
```
